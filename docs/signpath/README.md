# SignPath Foundation setup

Selected route, 26 October 2026: apply for free OSS signing with SignPath
Foundation. No Azure subscription or Entra tenant is needed for this route.
Approval is not automatic. No SignPath account, token, production configuration
or signature has been created for Folio yet. Existing installers are unsigned.

## Prepared locally

- `application-draft.md`: application description and bundled-data disclosure.
- `code-signing-policy-draft.md`: proposed process, privacy statement and roles.
- `app-artifact.xml`: proposed ZIP/app configuration, restricted to Folio's
  filename, product name and requested product version. This configuration
  alone does not sign an NSIS installer or its embedded uninstaller.
- `license-audit/`: book-by-book source metadata and review flags, generated by
  `python -X utf8 scripts/audit-library-licenses.py`. It reads SQLite in read-only
  mode and does not modify the application or its library.

## Resolve before publishing

1. Owner confirmed `bnoy-ilearnco/folio` and MIT for Folio's original code and
   integrated converter on 26 October 2026. `LICENSE` and component notices
   record this scope. The public repository has been created.
   Do not apply MIT to third-party assets.
2. Resolve bundled-text eligibility with the provider. The publisher intends
   free personal/noncommercial library use. After adding Mishnah/Bartenura,
   the current inventory has 90 CC-BY-NC editions and 22 unknown licenses.
   Also establish the exact versions and
   required notices for the other Creative Commons editions. Ask SignPath how
   its all-components OSS requirement applies to the data. Do not publish the
   current database/installer on an assumption of permission. The installed
   personal library stays intact during this review.
3. Audit dependency/font/runtime redistribution notices and source obligations.
   Exclude private sample documents, credentials, build outputs and local data
   from source publication. A local Git repository now uses branch `main` and
   remote `https://github.com/bnoy-ilearnco/folio.git`. The database and local QA
   screenshots are excluded. The remote repository exists; no signed release
   or text database is published as part of the initial source setup.
4. Publish the eligible source, documentation and a legitimate release/download
   page, then complete the Foundation application. Fill in the actual maintainer,
   organization and contact details privately. SignPath may require more project
   history or other changes before accepting a new project.

## After Foundation approval

1. Enable MFA on GitHub and SignPath. Install the SignPath GitHub app for the
   approved repository and link GitHub.com as the trusted build system.
2. Create the approved project, signing policies and artifact configurations.
   Use the real assigned identifiers, never example IDs. Restrict origin to
   the intended repository, reviewed branches/tags and workflow; require manual
   release approval. Configure the named approvers in both services.
3. Store `SIGNPATH_API_TOKEN` directly in a protected GitHub environment secret.
   Keep organization ID, project slug, signing-policy slug and artifact config
   slugs as non-secret GitHub environment variables. Never paste tokens in chat.
4. Complete and test the NSIS packaging sequence: build on a GitHub-hosted runner,
   export the generated uninstaller, upload Folio's app/uninstaller as workflow
   artifacts, obtain signatures, repackage those signed bytes without Tauri
   binary patching, then submit the final installer as a separate artifact.
   Preserve Microsoft's WebView2 signature. SignPath documents MSI deep signing;
   do not assume the same nested signing is available for NSIS.
5. The official submission action is
   `SignPath/github-action-submit-signing-request@v3`. Pin the reviewed commit;
   the v3 ref inspected on 26 October 2026 was
   `f6d04783b4569d051e0c80105fe66e82819d0092`.
   Supply `api-token`, `organization-id`, `project-slug`,
   `signing-policy-slug`, `artifact-configuration-slug`, `github-artifact-id`,
   `wait-for-completion: true`, and `output-artifact-directory`. Upload first;
   use the returned artifact ID. Pass the actual product version as a JSON
   string in `parameters`. Use the action's default connector endpoint.
6. Verify app, uninstaller and final installer with `Get-AuthenticodeSignature`:
   valid trust, approved signer and timestamp. Install/uninstall on a clean
   Windows machine and test first-run offline import/library access. Hash the
   signed final installer, not the earlier unsigned file. Only then publish it.
7. Publish the completed policy/attribution on the home and download pages.

The existing `windows.yml` runs frontend checks and gates unsigned native
packaging behind `FOLIO_LIBRARY_DISTRIBUTION_APPROVED=true`. Do not set this
until exact edition rights are documented. Its native job reconstructs the
corpus from the pinned source after clearance; no database is committed.
Local signing
helpers are for a separately owned certificate/service and do not activate
Foundation signing. No production workflow is enabled while rights and provider
approval are pending.
